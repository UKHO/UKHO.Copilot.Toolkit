## Findings

1. **High; actionable; original-criteria correction — body-only handoffs can satisfy the structural guard.** `scripts/verify-copilot-contracts.cjs`, `parseFrontmatter` and `checkHandoffs`: the former extracts only top-level frontmatter fields, but the latter searches the entire Markdown text for `^handoffs:` without requiring that field in the frontmatter. An agent with no frontmatter handoffs but an otherwise matching block in its body can pass the route check. This undermines A1's complete *declared* manual handoff validation. Bind block parsing to the frontmatter delimiters, require the declared field and add a body-only negative. This is a source deduction, not an executed mutation.
2. **High; actionable; original-criteria correction — bounded workflow validation misses disabling or expanding execution routes.** `scripts/check-copilot-workflow.cjs`, `top` extraction and trigger `filters`: the top-level regex ignores quoted YAML keys; a valid quoted workflow-level `"env":` before `name:` is not counted and can change the environment of all three Node checks (for example via `NODE_OPTIONS`) while the checked blocks and `CI-002` still pass. The filter grammar also accepts extra entries after the three required entries, including a later quoted negative pattern `'!**'` that excludes paths on both events; it does not require the workflow's own `.github/workflows/package.yml` path. Thus A1's checks-only and both-trigger reachability claims have false-PASS paths although the *current* workflow contains the self-path and no such extras. Reject unsupported top-level constructs and exclusion filters, require relevant guarded-path coverage (including the workflow itself), and test these cases separately for both triggers. No malicious workflow or actual disabled check was observed.
3. **Medium; actionable; original-criteria correction — post-sync Run Book ordering has no regression assertion.** `docs/run-books/vsix-packaging.md`, **Ordered process**, currently instructs inspection and a fresh manifest check after conditional sync. But `scripts/verify-vsix-packaging-guide.cjs` verifies the metadata block, script interfaces and workflow, while `scripts/verify-copilot-contracts.cjs` checks Run Book anchors and `scripts/test-copilot-contract-scenarios.cjs` changes metadata and CI, not this sequence. Restoring the stale pre-sync-check → sync → package prose would not fail these checks. A5 and the Plan matrix explicitly call for a focused sequence assertion and negative; add one without altering the six interfaces or authorizing packaging.
4. **Medium; actionable; original-criteria correction — projected-file latitude has no additive contradiction test.** `scripts/test-copilot-contract-scenarios.cjs`, `expect('projected worker files are not an exhaustive whitelist', [], pass)`, runs only a healthy baseline. `WORKER-001` in `scripts/verify-copilot-contracts.cjs` requires the correct clause in `.github/agents/implementation-worker.agent.md` but forbids only ignoring an explicit restriction; a new contradictory exhaustive projected-file whitelist could coexist with it and pass. A4 requires both projected-file latitude and explicit restrictions to remain guarded.
