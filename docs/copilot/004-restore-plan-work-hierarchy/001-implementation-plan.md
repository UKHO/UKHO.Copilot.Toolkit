# Implementation plan: Restore trackable plan work hierarchy

## Outcome and boundaries

- **Outcome and acceptance:** Future implementation Plans use one authoritative, numbered and initially unchecked Work Item register, with corresponding numbered, checkable Task and Step detail as the normal proportionate schema. Each Work Item traces to Research/requirements evidence and observable acceptance, with relevant item-level checks and dependencies. A small Plan may have one meaningful item, task and step; neither empty filler levels nor a mandatory minimum count beyond meaningful traceability is required. Completion markers show execution progress only, never validation pass, approval or Review acceptance.
- **Change boundary:** Prospectively revise `.github/skills/architecture-planning/implementation-plan-template.md` and its owning guidance in `.github/skills/architecture-planning/SKILL.md`; add focused static contract and mutation scenarios in `scripts/verify-copilot-contracts.cjs` and `scripts/test-copilot-contract-scenarios.cjs` where effective. Related in-boundary checks and fixtures may be selected by Implement. Do not change the lifecycle core, tool/agent permissions, handoffs, status/transition rules, public runtime behavior, dependencies, historical numbered Plans, packaging or VSIX artifacts. No installation, deployment or other external effect is authorized.
- **Approach:** Restore the useful structure from the historical [lightweight RPIR Plan](../../planning/002-lightweight-rpir-phase-documentation/001-implementation-plan.md) without copying its old operational restrictions or checked completion state. Replace the current template's optional Task/Step sentence and optional progress column with a single Work Item table and matching `### Work Item N` detail. Use ordered `Task N.M` and `Step N.M.K` unchecked markers and item-adjacent intended actions, dependencies where meaningful, acceptance and validation; keep IDs/rows/detail synchronized without a second rival register. Retain all current outcome, scope, assumptions, useful validation, safety/recovery, identity/lineage and manual-handoff guidance. Align the planning skill's Procedure 6 while preserving Plan ownership and Implement's discretion to diagnose and select related files/tests. Static assertions should defend authored meaning, not demand exhaustive micro-steps or imply runtime attachment.
