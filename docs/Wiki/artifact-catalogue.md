## Purpose and audience

**Purpose:** Locate the current GitHub Copilot customization artifacts, understand what each is for and how it activates, and follow the canonical source when maintenance is needed.

**Audience:** Toolkit maintainers and reviewers who need an inventory of the repository's `.github` artifacts. Readers should understand repository-relative paths and the distinction between source artifacts and their manifest registration.

## Prerequisites

- Read [Maintain the Toolkit](maintain-the-toolkit.md) for maintainer orientation before proposing an artifact change.
- Treat `.github/copilot-instructions.md`, the artifact-specific skills, and the lifecycle policy as canonical operational sources; this catalogue is descriptive and does not authorize changes.

## Content

Future RPIR output uses the lifecycle core's [shared reader-facing rule](../../.github/skills/rpir-lifecycle-core/SKILL.md#reader-facing-outputs) and four phase templates: current Research understanding/evidence, Plan deliverables/work, Implement delivery/checks, and Review's independent conclusion/findings. Link inspected predecessors rather than repeat them; omit Q&A/change histories and irrelevant empty categories, not required checks, actual conditions, exact ADR recording outcomes or checkpoint dispositions. This is authored guidance, not observed loading or live improvement; the [synthetic output pairs](../../.github/skills/rpir-stage-assurance/concise-output-scenarios.md) are assessment resources under the existing assurance skill.

### Activation and packaging model

The manifest registers one lifecycle instruction under `contributes.chatInstructions`, 18 agents under `contributes.chatAgents`, no prompt files under `contributes.chatPromptFiles`, and 23 Skills under `contributes.chatSkills`. The corresponding entries are also included by `package.json.files` (Skills by directory). These are literal manifest facts, not a claim of complete discovery, installed packaging or runtime activation. Activation remains governed by each artifact's metadata and Copilot surface:

- **Instructions** are authored to provide repository context when their scope applies. The repository-only root instruction is designated always-on here, not contributed to consumers; the contributed lifecycle-record instruction declares numbered-record `applyTo` patterns. A path match is only a candidate, not verified physical lifecycle identity or write authority. Runtime matching, discovery and attachment are not established here.
- **Agents** are selected by a user or delegated by an explicitly allowed coordinator. Coordinator agents are user-invocable unless metadata says otherwise; worker agents in this catalogue declare `user-invocable: false` and are intended for delegation.
- **Prompt files** are deliberate shortcuts where supported; none is currently contributed by the Toolkit. Availability and behavior depend on the actual Copilot surface.
- **Skills** may be selected when relevant, explicitly loaded by a role or user-invoked when metadata permits. Skills marked `user-invocable: false` are internal workflow capabilities. The five thin RPIR entries explicitly declare `user-invocable: true` and `disable-model-invocation: true`; select the receiving coordinator first, then deliberately invoke its Skill. They are not agent selectors or mandatory replacements for natural-language requests.
- **Subagents and handoffs** are runtime mechanisms, not additional file categories. Permitted-worker and nondelegation instructions are behavioral controls, not proof of a native per-parent filter or isolation. Unexpected exposed tools grant no authority.

All 18 agent paths are registered under `package.json` → `contributes.chatAgents` and included by `package.json.files`.

Each agent's source projects one Copilot runtime ID from its [canonical role profile](../../.github/skills/agent-model-selection/references/role-profiles.md). The current 18-role profile uses `hydrafusion` and omits `reasoning-effort` so Fusion manages reasoning. This source projection is a preference, not proof of installed dispatch; omission does not clear inherited or external configuration or establish effective effort. Report an unobservable effective model as "not observable" and an observed fallback with unavailable reason as "cause not exposed"; missing telemetry is not evidence of fallback, and a known wrong default is not a pass. Runtime routing and reasoning remain unverified.

For a new lifecycle Research selects an evidenced documentation root and its direct `copilot/` parent, then a contained numbered topic and Research brief; historical verified `docs/planning/` and `docs/delivery/` topics remain compatible without migration. Each effect needs actual containment and effective permission. Inspect the relevant inventory, select an absent non-overwriting number in the verified topic, save and read back the physical record and direct same-folder predecessor. A collision can be re-inspected and safely reallocated in the same topic; duplicate canonical fields, fingerprints, mandatory double inventories, status rituals and routine terminal probes are not required. An attachment or instruction `applyTo` match is not canonical identity or write authority. Static manifest/source inspection does not prove Copilot discovery or permission; runtime exercise requires separate authorization.

Use dropdown-first RPIR coordinator selection followed by deliberate manual entry Skill invocation, or a retained natural-language request, under policy already effective before invocation. The [core entry contract](../../.github/skills/rpir-lifecycle-core/SKILL.md#transitions-and-outcome-authority) binds explicit contextual/appended physical snapshots with qualifications; missing objective/predecessor or stale/conflicting inputs need clarification, never newest/default selection or placeholders. Verify actual receiver; mismatch needs manual selection, not impersonation/automatic dispatch/subagent substitution. Loading/picker/quote/tool-worker-output/automatic continuation/unsent text is not invocation. Research starts discovery without predecessor sign-off or later-readback acknowledgment; Plan signs off planning only; material Review-origin Plan needs chosen scope and the full Review -> report -> prior Plan -> Research chain. Implement authorizes bounded delivery and eligible exact decisions; Review admission is not acceptance or a partial pass. No duplicate routine sign-off or loaded-session self-upgrade. Original-criteria correction uses original Plan plus Review, fresh evidence and independent re-review; unresolved findings prevent acceptance. Canonical agents/methods/core remain the operational owners.

### Prompt files

No prompt files are contributed. A prefilled suggestion is not a sign-off or automatic submission. The prospective native route selects the intended receiving agent and deliberately sends a request with the inspected physical predecessor; it has no fixed wording or slash dependency. The policy effective at invocation governs any earlier required bootstrap route.
